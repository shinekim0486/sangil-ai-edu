S#4 팀별 패킷 설계 실습 — 주행 명령 패킷 완성 🔒 ›

팀의 차량이 속도 60km/h, 직진으로 주행하는 패킷을 설계하세요. 6개 필드를 모두 채우면 실시간으로 패킷이 생성됩니다.

💡 힌트: SOF는 항상 AA 55, TYPE은 주행 명령이므로 0x01, SEQ는 첫 번째 패킷이므로 00 00 00 01입니다.

① 명령 TYPE 선택

0x01 주행 명령
0x02 상태 요청
0x03 긴급 정지

S#5 검사합 토론 — XOR vs CRC-8 🔒 ›

패킷 오류를 검출하는 방법 두 가지를 비교해봅시다. 팀에서 어떤 방법이 더 낫다고 생각하나요?

XOR 검사합
✓ 계산이 매우 단순
✓ 처리 속도 빠름
✓ 구현 코드 3줄
✗ 2비트 동시 오류 미검출
✗ 연속 오류에 취약
✗ 오류 위치 파악 불가
CRC-8 검사합
✓ 연속 오류 강력 검출
✓ 차량 통신 표준(CAN Bus)
✓ 신뢰성 높음
✗ XOR보다 계산 복잡
✗ 오류 교정 불가 (검출만)
~ 3차시에 코드로 확정 예정
⚠ XOR 선택: 1차시에는 허용됩니다. 하지만 3차시 안전 검증 실습에서 CRC-8로 확정될 예정입니다. 이유를 기억해두세요!
✅ CRC-8 선택: 자율주행 차량 통신은 CAN Bus 표준을 따릅니다. CRC-8은 그 표준 중 하나예요. 3차시에서 실제 코드로 구현해봅니다.

S#6 주행 명령 전송 실습 🔒 ›

S#4에서 설계한 패킷으로 주행 명령을 전송합니다. 터미널 출력을 확인하세요.

[PACKET] AA 55 01 00 02 00 00 00 01 3C 00 A3
[INFO] 전송 완료 · 12 bytes · seq=1
[ACK] CAR-ECU 응답: 주행 명령 수신 확인
[LATENCY] 편도 제어 지연: 595ms (목표: 11.6ms)

⚠ 지연 시간 주목: 현재 595ms → 목표 11.6ms
지연(ms) × 0.025 = 이동 거리(cm)
595ms × 0.025 = 14.9cm 이동 후 반응 — 이것이 2차시의 핵심 문제입니다!

AUTO-NET LAB 패킷 형식 v1

팀: -

필드 구성 (6개):
· SOF: AA 55 (2B) — 패킷 시작 표시
· TYPE: 0x01 (1B) — 명령 종류
· LENGTH: (2B) — PAYLOAD 크기
· SEQ: (4B) — 순서 번호
· PAYLOAD: (가변) — 실제 데이터
· CHECKSUM: CRC-8 (1B) — 오류 검출

TYPE 정의:
· 0x01 주행 명령 · 0x02 상태 요청 · 0x03 긴급정지

검사합: - 방식 (3차시 CRC-8 확정)
