## 1. 1·2차시 학습 내용 회고

### 2차시 오개념 교정

- **오개념**: LENGTH 오개념 영향 없음 → 표본 30회 이상 필요성 인식(2차시)
- **도움말**: 기아 현상(starvation) 개념 + 트레이드오프 분석
- **의문**: 정지 우선화 시 센서 RTT 증가(102ms) → 대기 한계 설정 필요

|---|---|

| 단축 효과 | 34.099999999999994 ms |
| 센서 지연 | 102 ms |

## 2. 안전규칙 설계

### 팀 공통: 정지 명령 우선화

**규칙**: 정지 명령(TYPE 03)을 다른 데이터보다 먼저 전송

**근거 (2차시 측정)**:
- 기준: RTT 95.1ms → 61ms로 단축 확인
- 유실: 1건 → 0건 (분할 팀) / 1건 유지 (우선순위 팀)
- 효과: 34.099999999999994ms 단축 (정지 명령 기준)

**한계**:
- 센서 RTT 부작용: 95.1ms → 102ms (증가)
- 대기 한계 필요 (센서 무한정 밀림 방지)

### 개인 검토 사항

**CAR1 안전성 검토**

- 2차시 결과: 정지 명령 95.1ms → 61ms
- 센서 부작용: 102ms (증가 관찰)
- 안전 판단: 우선순위 조정 필요 (센서 기아 현상 방지)

**3차시 검증 포인트**
- 센서 RTT 상한선 설정 (대기 시간 제한)
- 기아 현상(starvation) 개념 + 트레이드오프 분석 필요

## 3. 검증 방법 (3차시)

**기준 조건**: 2차시 RTT 95.1ms, 유실 1건

**검증 절차**:
- 정지 우선화 규칙 적용 전후 비교
- 센서 지연 모니터링 (대기 한계 설정 확인)

**예상값**: 61ms 이상 단축 (정지 명령 기준)

## 4. 45초 팀 발표

저희 팀은 2차시 측정값(RTT 95.1ms → 61ms)을 기준으로 정지 명령 우선화 규칙을 설계했습니다. 정지 신호 34.099999999999994ms 단축 효과를 확인했지만, 센서 RTT가 102ms로 증가하는 트레이드오프를 발견했습니다. 3차시에는 이 규칙이 안전성(센서 밀림 방지)을 보장하는지 검증합니다.

### 개인 회고 (3문장)

- 2차시에서 배운 것:  표본 30회 이상 필요성 인식(2차시)
- 본 증거: RTT 95.1ms → 61ms 단축 (정지 명령), 센서는 102ms (증가)
- 3차시 안전규칙 설계 판단: 센서 밀림과 정지 신호 속도 모두 고려한 우선순위 설정
