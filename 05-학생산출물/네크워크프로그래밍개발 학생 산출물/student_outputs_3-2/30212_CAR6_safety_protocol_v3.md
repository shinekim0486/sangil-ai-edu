## 1단계: 안전규칙 근거 기획 (장면 S#15-16)

### 🟦 팀 공통 — 정지 명령 우선화 원칙

- **규칙명**: CAR6 팀 정지 명령 우선 규칙

### 🟩 개인 (학번 30212_CAR6) — 규칙 근거 의논

**S#15: "막연한 규칙 → 근거 있는 규칙"**

| 단계 | 내용 |
|---|---|
| 첫 의문 | 우리 팀이 정한 RTT 기준값이 정말 안전한가? |
| 근거 찾기 | 2차시 측정값: 기준 → 정지명령, 센서 RTT 비교 |
| 근거 제안 | 정지 명령 RTT가 센서보다 일정% 이상 단축되면 안전 |
| 동료 피드백 | 팀원들이 같은 조건에서 측정하면 기준값도 비슷할 것 같아요. |

**S#16: "비교 경쟁의식 → 조건 통일"**

| 단계 | 내용 |
|---|---|
| 다른 팀 비교 | A팀(우선순위 큐): 61ms / B팀(분할): 58ms |
| 조건 통일 여부 | 기준값은 다르지만 개선 비율(%) 유사 |
| 수정 사항 | 상대값(%) 규칙으로 통일: "기준값의 65% 이하" |

## 3단계: 45초 발표 요약 & 3문장 회고 (S#19)

**발표 내용** 🟦
> 저희 팀은 2차시 측정값을 근거로 정지 명령을 우선 처리하는 규칙을 정했습니다. 조건은 TYPE 03 감지 + 기준값의 65% RTT 단축, 한계는 표본 10회와 측정 환경 제한입니다. 앞으로 실제 차량과 장비를 연결해 재검증할 예정입니다.

**3문장 회고** 🟩
- 처음 생각: 우선순위 큐/분할로 모든 데이터가 다 빨라질 줄 알았어요.
- 본 증거: 정지 명령만 빨라지고 센서는 늦어졌어요. 그림으로 보니 우선순위 효과가 명확했어요.
- 바뀐 판단: 우선순위는 순서를 바꾸는 것이지, 평균을 낮추는 게 아닙니다.

## 4단계: 팀 협력 & 인계 메모

### 팀원과의 의논 (S#16-18)

| 의문점 | 팀원 답변 | 우리 결정 |
|---|---|---|
| 다른 팀(B팀)도 우리 규칙을 쓸 수 있을까? | 방식이 다르므로 각각 적용. 효과는 비슷하지만 조건이 다릅니다. | 규칙에 반영 ✓ |
| 우리 팀이 정한 RTT 기준값이 정말 안전한가? | 2차시 측정값 범위(85~140ms)에서도 65% 이하인지 재확인 필요. | 다음 단계 계획 |
| 정지 명령 우선순위를 게임팀에 어떻게 구현해 달라고 할까? | TYPE 03 패킷에 높은 우선순위 플래그 추가 요청. | 추가 검증 필요 |

### 인계 메모 (4차시로)

- 우선 확인할 것: 정지 명령 유실 시 재전송 절차 확인
- 실제 차량 연결 시 예상 문제: 차량이 멀어지면 RTT가 기준값보다 훨씬 커질 가능성
- 다른 팀과 협력 필요: 게임팀·서버팀과 우선순위 구현 및 실제 차량 테스트
