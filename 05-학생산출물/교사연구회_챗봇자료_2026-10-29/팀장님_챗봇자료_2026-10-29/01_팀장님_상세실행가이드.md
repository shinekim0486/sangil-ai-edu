# 팀장님 챗봇 로컬 실행 가이드

교사연구회 교사용 전달본 | 2026년 10월 29일

## 1 먼저 실행할 파일을 확인합니다

팀장님께 챗봇의 수업 목적과 운영 구조를 공유하고, Windows PC에서 직접 실행할 수 있도록 준비한 자료입니다. 화면 체험부터 시작한 뒤 실제 AI 답변을 사용할 때만 팀장님이 관리하는 API 키를 설정하시면 됩니다. 개발자의 API 키와 학생 대화 기록은 들어 있지 않습니다.

| 목적 | 실행 또는 열기 |
|---|---|
| 키 없이 화면과 흐름 확인 | 묶음 맨 위의 01_화면체험.cmd를 더블클릭합니다. |
| 실제 AI 답변 사용 | 02_실제챗봇실행.cmd를 더블클릭합니다. 처음 한 번 API 키를 입력합니다. |
| 상세 절차 읽기 | 01_팀장님_상세실행가이드.docx를 엽니다. 같은 내용의 .md도 있습니다. |
| 챗봇 원리와 교육 설계 확인 | 03_설계근거자료의 설계 명세서와 이중 매핑표를 봅니다. |

이 챗봇은 웹브라우저로 쓰지만 웹사이트 파일만 여는 구조가 아닙니다. 이 PC에서 실행한 서버가 화면을 제공하고, 실제 모드에서는 질문 문맥을 OpenAI API로 보내 답변을 받아옵니다. 인터넷에 공개하지 않고 같은 학교망에서 사용할 수 있습니다.

사용 전 조건은 Windows 64비트 PC, ZIP 전체를 풀 공간, Edge 또는 Chrome입니다. Python과 패키지는 동봉했습니다. 실제 모드는 인터넷과 유효한 API 키가 필요하지만 체험 모드는 API를 호출하지 않습니다.

묶음은 교사용입니다. 학생에게는 압축파일이나 서버 폴더를 주지 않고 접속 주소와 팀 코드만 안내합니다. 실제 학생 수업에 적용하기 전에는 담당 교사가 답변 범위와 장비 조건을 확인합니다.

## 2 압축을 풀고 화면 체험을 시작합니다

1. 받은 ZIP 파일을 마우스 오른쪽 클릭하고 모두 압축 풀기를 선택합니다. 권장 위치는 C:\teacher-chatbot입니다. ZIP을 연 창 안에서 실행하지 않습니다.

2. 압축을 푼 안쪽 폴더에서 00_먼저읽기.txt와 01_화면체험.cmd가 함께 보이는지 확인합니다. 실행파일만 따로 바탕화면으로 옮기지 않습니다. 바로가기는 만들어도 됩니다.

3. 01_화면체험.cmd를 더블클릭합니다. 검은 실행 창에 체험 모드와 http://127.0.0.1:5001 주소가 표시될 때까지 기다립니다.

4. Edge 또는 Chrome의 주소창에 http://127.0.0.1:5001을 입력합니다. 검색창 대신 주소창을 사용하고 http를 https로 바꾸지 않습니다.

5. 팀 코드에는 DEMO를 입력합니다. 이 체험 모드에는 접속 코드를 넣지 않습니다. 시작 화면의 소개 단계를 지나 채팅 화면까지 이동합니다.

6. 처음 질문에는 상태를 확인하는 역질문이 나오는지 봅니다. 체험 모드는 정해진 모의 답변이므로 실제 AI 답변의 정확성이나 교과 분류 성능을 평가하는 용도로 쓰지 않습니다.

7. 끝나면 실행 창에서 Ctrl+C를 누르거나 창을 닫습니다. 브라우저 탭만 닫으면 서버가 계속 켜져 있을 수 있습니다.

체험 기록은 02_챗봇_실행폴더 안의 demo_data에만 저장합니다. 기존 .env가 있더라도 체험 실행기는 API 클라이언트를 만들지 않습니다. 포트 5001은 이 PC 안에서만 열리고 다른 학생 PC의 접속용으로 제공하지 않습니다.

Windows에서 실행 경고가 나오면 전달받은 파일과 출처를 확인합니다. 학교 보안 정책이 차단하면 담당자에게 허용 여부를 확인하며, 보안 프로그램을 끄거나 전역 설정을 바꾸지 않습니다.

## 3 API 키를 넣고 실제 챗봇을 켭니다

1. 체험과 별개로 실제 AI 응답을 쓸 때 02_실제챗봇실행.cmd를 더블클릭합니다. 내부의 start.bat을 통해 서버를 시작합니다.

2. 처음 실행하면 OpenAI API 키를 입력하라는 안내가 나옵니다. 팀장님 또는 학교에서 사용을 승인한 키를 해당 검은 창에 붙여 넣고 Enter를 누릅니다. 키 입력은 정상적으로 화면에 표시되지 않을 수 있습니다.

3. 팀 코드 목록을 입력합니다. 그대로 Enter를 누르면 CAR1,CAR2,CAR3,CAR4,CAR5,CAR6을 사용합니다. 혼자 확인할 때는 CAR1을 사용하면 됩니다. 직접 정할 때는 영문·숫자 코드를 쉼표로 구분합니다.

4. 공통 접속 코드를 정합니다. 혼자 시험할 때는 비워 둘 수 있습니다. 수업에 사용할 때는 교사가 별도로 정해 학생에게 전달합니다. 팀 코드와 접속 코드는 서로 다른 값입니다.

5. 화면에 표시되는 관리자 열쇠를 따로 보관합니다. 대화 기록 내보내기용이며 학생에게 공개하지 않습니다. 설정은 02_챗봇_실행폴더의 .env 파일에 저장됩니다.

6. 실행 창에 모드 OpenAI 연결됨과 http://127.0.0.1:5000이 보이는지 확인합니다. 이 표시는 키로 클라이언트를 구성했다는 뜻입니다. 실제 키의 유효성·잔액·네트워크 상태는 첫 유료 요청 시 확인됩니다.

7. 브라우저에서 http://127.0.0.1:5000을 열고 CAR1과 정한 접속 코드를 입력합니다. 본문에 있는 시연 예시처럼 짧은 대화를 진행합니다. 실제 모드의 질문은 API 사용량과 비용을 발생시킵니다.

API 키를 채팅창, 문서, 학생 화면에 붙여 넣지 않습니다. 작성자의 기존 키를 복사한 .env는 배포하지 않았습니다. 키가 없으면 체험 모드로 화면만 확인할 수 있습니다. 모의 응답이라고 표시되면 실제 AI 모드로 작동하는 상태가 아닙니다.

설정을 고칠 때는 서버를 먼저 종료한 뒤 .env를 메모장으로 엽니다. 파일 탐색기의 보기 메뉴에서 파일 확장명 표시를 켜 두면 .env.txt로 잘못 저장하는 것을 막을 수 있습니다. 키 값 외의 실제 설정 내용도 학생에게 공유하지 않습니다.

## 4 학생 PC에서 같은 서버에 접속합니다

팀장님 혼자 시험할 때는 이 절을 건너뛰어도 됩니다. 수업에서는 서버 역할 PC 한 대만 실제 챗봇을 실행합니다. 학생 PC에는 Python이나 이 ZIP을 설치하지 않습니다.

| 사용 위치 | 브라우저 주소 | 조건 |
|---|---|---|
| 서버 PC 혼자 체험 | http://127.0.0.1:5001 | 체험 실행, 팀 코드 DEMO. |
| 서버 PC 실제 답변 | http://127.0.0.1:5000 | 실제 실행, 설정한 팀 코드. |
| 학생 PC 실제 답변 | http://서버의 IPv4주소:5000 | 같은 학교망에서 서버 창의 학생 접속 주소 사용. |

1. 서버 PC와 학생 PC를 같은 교내 유선망 또는 서로 통신 가능한 무선망에 연결합니다. 같은 학교에 있어도 교육망·행정망·게스트망이 분리되어 있으면 접속되지 않을 수 있습니다.

2. 서버 실행 창에 표시된 학생 접속 주소를 확인합니다. 예를 들어 http://192.168.0.23:5000 형식이지만 실제 주소는 PC마다 다릅니다. 이 예시 주소를 그대로 사용하지 않습니다.

3. 학생 PC 한 대에서 먼저 해당 주소를 열고 로그인까지 확인합니다. 학생에게 127.0.0.1을 주면 학생 자신의 PC를 가리키므로 서버에 접속되지 않습니다.

4. 서버 PC에서는 화면이 열리는데 학생 PC에서만 안 열리면, 같은 망과 주소를 확인한 뒤 학교 정책이 허용하는 경우에만 실행 폴더의 방화벽_허용.bat을 관리자 권한으로 실행합니다. 이 파일은 TCP 5000 수신 허용 규칙을 만듭니다.

5. 방화벽 설정 후에도 실패하면 전산 담당자에게 학생망에서 서버 PC의 TCP 5000 통신이 가능한지 확인합니다. 검사 목적만으로 공유기 포트포워딩이나 인터넷 공개를 설정하지 않습니다.

실행 창이 닫히거나 서버 PC가 절전 상태로 들어가면 학생 접속도 중단됩니다. 수업 동안 창을 최소화해 두고, 서버 IP가 바뀌면 새 주소를 안내합니다. 학교망에서의 다중 PC 접속은 현장에서 별도 확인해야 합니다.

## 5 챗봇의 수업 구조와 시연 대화를 이해합니다

챗봇은 하나이며 교사가 작성한 스킬 문서 8종을 공정에 맞춰 사용합니다. 응용프로그래밍의 화면·서버 역할을 나누어 담았기 때문에 스킬 문서 8종과 교과 7개를 구분합니다. 학생은 과목 선택 대신 자기 작업과 문제를 말합니다.

| 단계 | 확인할 동작 |
|---|---|
| S0 | 첫 질문의 목표·현재 상태·장애 중 부족한 내용을 되묻습니다. |
| S1 | 확보한 내용을 요약하고 접근 방향을 제시합니다. |
| S2 | 공정이 확인되면 구체적 절차와 개념을 제시합니다. |
| S3 | 학생의 시도 근거가 있으면 코드 또는 요청한 관찰 보고를 제공합니다. |

횟수만 채워도 코드가 나오는 구조는 아닙니다. 최소 턴 수와 확보된 정보, 공정, 시도 흔적을 서버가 함께 판단하므로 네 번을 질문해도 S3가 아닐 수 있습니다. S3 도달이 답변 정확성이나 실물 완주를 뜻하지도 않습니다.

시연 입력 예시 1: JSP와 Oracle로 주행 기록 조회 화면을 만들고 있습니다. 테이블에는 기록이 있는데 웹 화면은 빈 표입니다. 어디를 먼저 확인하면 좋을까요?

시연 입력 예시 2: 챗봇이 물은 항목에 답합니다. 조회 SQL을 직접 실행하면 12행이 나옵니다. 지금은 JSP에서 DAO의 findAll을 부르고 있습니다.

시연 입력 예시 3: 실제로 확인한 코드·로그를 제시합니다. ResultSet에서 DTO를 만들었지만 list.add(dto)는 빠져 있습니다. 이것이 원인인지 확인하고 싶습니다.

시연 입력 예시 4: 수정 후 실제 확인 결과를 말하고 전체 메서드와 테스트 방법을 요청합니다. 이 예시는 대화 흐름을 설명하는 연습 자료이므로 실제로 실행하지 않은 결과를 실습 성과로 기록하지 않습니다.

운영 기준은 학생 세션 하루 60회, 팀 하루 200회입니다. 팀 코드만 입력하는 구조이므로 이를 실명 학생 인증이나 엄격한 개인별 한도 보장으로 해석하지 않습니다. 새로운 세션 생성과 팀별 사용량을 교사가 함께 관리해야 합니다.

## 6 자료를 점검하고 기록을 보관합니다

| 파일 또는 폴더 | 역할 |
|---|---|
| app.py / gate.py | 웹 요청, 단계 판정, 답변 검사입니다. |
| llm.py / pipeline.py | API 호출과 모델 선택, 공정 및 표준 규격입니다. |
| skills/*.md | 3D·게임·AI·네트워크·스마트앱·응용 서버·응용 화면·운영 스킬 8종입니다. |
| .env | 처음 설정할 때 생기는 API 키·팀 코드·관리자 열쇠입니다. |
| data.db / uploads | 실제 대화와 사용량 기록 / 사용자가 올린 파일입니다. |
| demo_data | 체험 모드 전용 기록입니다. 실제 수업 기록과 분리합니다. |

백업은 서버를 종료한 뒤 진행합니다. 실제 실행 폴더에서 .env, data.db, uploads를 날짜별 별도 폴더로 복사합니다. DB 옆에 data.db-wal 또는 data.db-shm이 남아 있으면 함께 보존하고 임의로 삭제하지 않습니다.

백업.bat도 동봉했지만 실행 중인 DB를 단순 복사하는 방식이므로 반드시 서버 종료 후 사용합니다. 백업에는 API 키와 학생 자료가 들어갈 수 있어 팀장님이 보관 권한을 관리합니다.

기록 내보내기는 서버 PC에서 http://127.0.0.1:5000/admin/export?key=관리자열쇠 형식을 사용합니다. 관리자열쇠 자리에 본인 .env의 ADMIN_KEY 값을 넣습니다. 주소가 포함된 화면도 학생에게 공유하지 않습니다.

다른 최신판으로 바꿀 때는 기존 폴더를 지우거나 새 압축을 덮어쓰지 않습니다. 다른 폴더에 새로 풀고 백업한 설정과 기록을 옮긴 뒤 실행 여부를 확인합니다.

스킬 문서는 담당 교사가 수업 범위와 실측 근거를 확인해 고칩니다. 개인정보나 API 키, 장비 접속 암호를 스킬에 넣지 않습니다. 파일을 고친 뒤에는 서버를 재시작해 동작을 확인합니다. 계획·교재 원문과 실행 코드가 다르면 pipeline.py 및 실제 동작을 먼저 대조합니다.

## 7 자주 생기는 문제를 순서대로 확인합니다

| 증상 | 먼저 확인할 것과 조치 |
|---|---|
| 검은 창이 바로 닫힘 | 압축을 전부 풀었는지, runtime 폴더가 있는지 확인합니다. 실행 창의 마지막 오류를 확인하며 키가 보이는 부분은 가립니다. |
| runtime 또는 모듈을 못 찾음 | 실행파일만 옮기지 않았는지 확인합니다. Python을 새로 설치하기 전에 ZIP을 새 폴더에 다시 풉니다. |
| 주소를 열 수 없음 | 체험은 5001, 실제는 5000인지와 서버 창이 켜져 있는지 확인합니다. |
| 포트가 이미 사용 중 | 동일 실행 창이 두 개 켜져 있는지 확인합니다. 소유자를 모르는 프로세스를 종료하지 않습니다. |
| 팀 코드가 틀렸다고 나옴 | 체험은 DEMO, 실제는 처음 정한 CAR1 등의 코드인지 구분합니다. 접속 코드도 따로 확인합니다. |
