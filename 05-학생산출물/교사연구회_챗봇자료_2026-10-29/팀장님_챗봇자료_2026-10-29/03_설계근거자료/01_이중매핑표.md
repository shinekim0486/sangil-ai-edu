**성취기준(학습축) × NCS 능력단위요소(산업축)**

- 연구 주제: AI 챗봇 기반 전문교과 융합 수업 — 자율주행자동차 제작
- 대상: 3학년 3학급 34명 (1반 11 · 2반 12 · 3반 11)

- 근거 문서: 2022 개정 전문 교과 교육과정 별책25(문화·예술·디자인·방송) · 별책34(전기·전자) · 별책35(정보·통신), NCS 학습모듈 14종

## 0. 제작 공정 — 14단계 / 4트랙 / 8교사

자율주행차를 어떤 순서로 만드는지가 이 연구의 뼈대다. 학생은 이 순서를 따라가고, 챗봇은 역질문으로 학생이 지금 몇 단계인지 알아낸 뒤 거기서부터 돕는다.

```
                     P0 규격 정하기
                      │
        D1 운영 체계 ─┤  ← 1주차부터 6주 내내 상시
                      │
      ┌───────────────┴───────────────┐
   B코스 (실체)                    A코스 (지능과 검증)
   B1 차체 설계                    A1 시뮬레이터 구축
   B2 조립·출력                    A2 학습 데이터 생성
   B3 결선·기본 주행 *             A3 인식 모델 학습
   B4 센서 읽기                    A4 관제 화면 설계
   B5 통신 프로토콜
      └───────────────┬───────────────┘
            C1 모델 탑재    C2 관제 시스템 구현
                      └──┬──┘
              C3 통합 주행 시험 → 최종 주행

   * B3는 차체(B2)를 기다리지 않는다. 브레드보드로 먼저 시작한다.
```

| 단계 | 이름 | 담당 과목 | 선행 | 완료 판정 |
|---|---|---|---|---|
| **P0** *(평가 밖)* | 규격 정하기 | 전 과목 | — | 프로젝트 메모에 보드 종류·센서 핀 번호·차체 치수가 적혀 있다. |
| **D1** *(상시)* | 운영 체계 | 시스템 운영 및 네트워크 운영 | P0 | 6주 동안 정한 토큰 예산 안에서 서버가 살아 있고, 장애가 언제 왜 났고 어떻게 처리했는지 적은 운영 기록… |
| **B1** | 차체 설계 | 3D 프린터용 제품 제작 | P0 | 파트 5개가 각각 저장되어 있고, 치수를 바꿔도 형상이 깨지지 않는다. |
| **B2** | 조립·출력 | 3D 프린터용 제품 제작 | B1 | 실물 차체가 조립되고 그 위에 보드와 모터가 흔들리지 않게 얹힌다 |
| **B3** *(평가 밖)* | 결선·기본 주행 | 네트워크 프로그래밍 | P0 | 명령을 주면 차가 원하는 방향으로 원하는 속도로 움직인다. |
| **B4** *(평가 밖)* | 센서 읽기 | 네트워크 프로그래밍 | B3 | 시리얼에 세 센서 값이 안정적으로 찍히고, 차선 위와 밖이 값으로 구분된다. |
| **B5** | 통신 프로토콜 | 네트워크 프로그래밍 | B4 | PC에서 실시간으로 센서 값을 받고, PC가 보낸 명령대로 차가 움직인다. |
| **A1** | 시뮬레이터 구축 | 게임 프로그래밍 | P0 | 가상 트랙에서 차가 달리고, 장애물에 부딪히면 멈추고, 미션 성공·실패가 판정된다. |
| **A2** | 학습 데이터 생성 | 게임 프로그래밍 · 인공지능 모델링 | A1 | 이미지와 라벨이 쌍으로 쌓이고, 실차 주행을 화면으로 되돌려 볼 수 있다. |
| **A3** | 인식 모델 학습 | 인공지능 모델링 | A2 | 시뮬레이터 화면에서 정한 목표 인식률이 나오고, 왜 그 성능인지 설명할 수 있다. |
| **A4** | 관제 화면 설계 | 스마트 문화 앱 콘텐츠 제작 | P0 | 시안과 스타일 가이드가 나오고, 응용 프로그래밍(화면) 팀이 그대로 구현할 수 있다. |
| **C1** | 모델 탑재 | 인공지능 모델링 · 네트워크 프로그래밍 | A3·B5·B2 | 실제 트랙에서 차가 정지선 앞에 스스로 선다. |
| **C2** | 관제 시스템 구현 | 응용 프로그래밍 개발(화면) · 응용 프로그래밍 개발(서버) | A4·B5 | 브라우저에서 우리 팀 주행 기록을 조회할 수 있고, 시안대로 화면이 나오며, 다음 시간에 다시 열어도 기록이… |
| **C3** | 통합 주행 시험 → 최종 주행 | 네트워크 프로그래밍 · 게임 프로그래밍 · 인공지능 모델링 | C1·C2 | 통신 지연과 패킷 유실을 측정한 값이 있고, 개선 전후를 비교한 기록이 남는다 |

**트랙 구분**

| 트랙 | 성격 | 과목 |
|---|---|---|
| **B** | 실체 — 차를 만들고 움직인다 | 3D 프린터용 제품 제작 · 네트워크 프로그래밍 |
| **A** | 지능과 검증 — 판단하게 하고 가상에서 검증한다 | 게임 프로그래밍 · 인공지능 모델링 · 스마트 문화 앱 콘텐츠 제작 |
| **C** | 합류 — 두 코스가 만나 완성된다 | 인공지능 모델링 · 네트워크 프로그래밍 · 응용 프로그래밍 개발(화면) · 응용 프로그래밍 개발(서버) · 게임 프로그래밍 |
| **D** | 운영 — 전 과정을 떠받친다 (1~6주 상시) | 시스템 운영 및 네트워크 운영 |

**교과가 맞물리는 접점**

| 흐름 | 주고받는 것 |
|---|---|
| D1 시스템 운영 및 네트워크 운영 → C2 응용 프로그래밍 개발(화면) · 응용 프로그래밍 개발(서버) | 서버 환경과 배포 절차 |
| B2 3D 프린터용 제품 제작 → C1 인공지능 모델링 · 네트워크 프로그래밍 | 센서 마운트 치수와 장착 규격 |
| B5 네트워크 프로그래밍 → A2 게임 프로그래밍 · 인공지능 모델링 | 실차 주행 로그 |
| A2 게임 프로그래밍 · 인공지능 모델링 → A3 인공지능 모델링 | 이미지와 라벨 데이터 |
| A3 인공지능 모델링 → C1 인공지능 모델링 · 네트워크 프로그래밍 | 학습된 인식 모델 |
| A4 스마트 문화 앱 콘텐츠 제작 → C2 응용 프로그래밍 개발(화면) · 응용 프로그래밍 개발(서버) | 시안과 스타일 가이드 |
| C2 응용 프로그래밍 개발(화면) · 응용 프로그래밍 개발(서버) → D1 시스템 운영 및 네트워크 운영 | 배포할 관제 서버 |

A코스와 B코스가 C에서 만나지 않으면 차가 완성되지 않는다. **융합이 선택이 아니라 조건이다.**

배정 능력단위가 「네트워크 프로그램 **최적화**」이고 NCS 학습 구성도 *시험·디버깅·코드 최적화*이므로, **완주하지 못해도 능력단위는 충족된다.** 완주를 판정 기준으로 삼으면 6팀 중 몇 팀은 반드시 미달로 끝나므로, 측정과 개선 과정을 평가하고 완주는 도전 과제로 둔다.
