## 1. 이 과목이 자율주행차에서 만드는 것

자율주행차 관제 시스템의 화면. 스마트 문화 앱 팀에게 받은 시안과 스타일 가이드를 실제로 구현하고, 조회·필터 같은 화면 제어를 붙이고, 단위 테스트와 사용성 테스트를 한다.

> 선생님이 만든 챗봇도 같은 구조의 웹 화면이다. 막히면 그 소스를 열어 보고 참고해도 된다.

## 2. 최종 도달점 — 완성 판정 기준

- [ ] 시안과 스타일 가이드를 확인하고 구현할 항목을 목록으로 정리했다
- [ ] 화면이 시안대로 나온다
- [ ] 조회·필터·정렬 같은 화면 제어가 동작한다
- [ ] 서버와 연결되어 실제 주행 데이터가 화면에 나온다
- [ ] 사용성 테스트를 하고 결과를 반영했다
- [ ] 다음 시간에 다시 열어도 기록이 그대로 남아 있다

## 3. 단계별 경로

| 단계 | 해야 할 것 | 완료 판정 | 자주 막히는 지점 |
|---|---|---|---|
| 1. UI 설계 확인 | 시안과 스타일 가이드를 읽고 무엇을 만들어야 하는지 항목으로 뽑는다 | 구현 항목 목록이 있다 | 시안 없이 감으로 시작함 |
| 2. UI 구현 | HTML과 CSS로 화면을 만든다. 색과 글자 크기는 스타일 가이드 값을 그대로 쓴다 | 시안과 눈으로 비교해 같다 | 마음대로 바꿔서 설계 팀과 어긋남 |
| 3. UI 제어 구현 | 버튼·조회·정렬 같은 동작과 입력값 검사를 붙인다 | 눌렀을 때 의도대로 반응한다 | 입력값 검사를 안 해 빈 값으로 조회함 |
| 4. 서버 연동 | 서버가 준 데이터를 받아 화면에 뿌린다 | 실제 주행 기록이 표와 그래프에 나온다 | 임시로 넣은 가짜 데이터로 끝냄 |
| 5. 테스트 | 화면 단위로 시험하고, 다른 팀 학생에게 써 보게 한 뒤 결과를 반영한다 | 테스트 기록과 수정 내역이 있다 | 본인만 써 보고 끝냄 |

## 4. 검증된 예시 코드·자료

**코드에서 반드시 지킬 것** — 아래는 팀마다 바꾸지 않는다. 다르게 하면 틀린 것이다.

| 항목 | 값 |
|---|---|
| DB 접근 방식 | **DTO/DAO** — 2학기 규칙. 화면 JSP는 서버 팀 DAO가 돌려준 DTO 목록을 받아 그리기만 하고 JSP 안에서 DB에 직접 연결하지 않는다 |
| 한글 인코딩 | `page contentType`과 `setCharacterEncoding` **둘 다** 넣는다. 하나만 넣으면 깨진다 |
| 그래도 한글이 깨지면 | **DB 문자셋**을 본다. `SELECT * FROM nls_database_parameters WHERE parameter LIKE '%CHARACTERSET%'` |
| 그래프 | 외부 라이브러리를 받지 않고 **canvas에 직접 그린다.** 값 목록을 받아 선으로 잇는다 |
| 표에 뿌릴 행 수 | 전부 그리면 화면이 무겁다. **앞 50행만** 그리고 나머지는 개수만 표시 |
| 표 정렬 | **SQL의 ORDER BY**로 한다. 자바스크립트로 정렬하지 않는다 |
| 색·글자 크기 | **CSS 맨 위에 변수로 모아 두고** 그것만 쓴다 |
| 시안 | **임의로 바꾸지 않는다.** 바꿔야 하면 설계 팀과 먼저 합의한다 |
| 사용성 테스트 | **다른 팀 학생 3명**에게 과제를 주고 설명 없이 지켜본다 |
| 주행 로그 출처 | **라즈베리파이**가 보낸 기록이다. PC가 아니다 |
| 그래프에 넣을 기준선 | **정지선 인식 250 mm** 와 **이탈 한계 85 mm** 두 개 |
| 새로 표시할 값 | **모델 조향값**(−1 ~ +1). 조도 센서 값과 나란히 보여 준다 |
| 한 회차 행 수 | 약 **900행** (한 바퀴 11.14 m · 초당 20건). 앞 50행만 그린다 |

**우리 수업 방식** — JSP와 Oracle을 쓴다. **2학기 규칙대로 DTO/DAO를 쓴다.** 화면 JSP는 서버 팀의 DAO가 돌려준 DTO 목록을 받아 그리기만 하고, JSP 안에서 DB에 직접 연결하지 않는다. 1학기에 만든 로그인·회원가입(JSP 안에서 직접 연결)과는 구조가 다르다.

**한글이 깨질 때** — 아래 두 가지를 모두 넣어야 한다. 하나만 넣으면 깨진다.

    <%@ page contentType="text/html; charset=UTF-8" %>
    request.setCharacterEncoding("UTF-8");

**표 정렬** — 자바스크립트로 정렬하지 말고 SQL의 ORDER BY 로 정렬해 가져온다. 데이터가 많아져도 화면이 느려지지 않는다.

**그래프** — 외부 라이브러리를 받지 않고 canvas 요소에 직접 그릴 수 있다. 서버에서 값 목록만 받아 선으로 잇는다. 축 눈금과 기준선까지 그리면 관제 화면으로 충분하다.

**스타일 가이드 지키기** — 색 코드와 글자 크기를 CSS 맨 위에 변수로 모아 두고 그것만 쓴다. 그러면 가이드가 바뀌어도 한 곳만 고치면 된다.

**사용성 테스트 방법** — 다른 팀 학생 세 명에게 "우리 팀 3회차 주행에서 가장 늦게 반응한 순간을 찾아라" 같은 과제를 주고, 어디서 망설이는지 말없이 지켜보며 기록한다. 설명해 주면 안 된다. 설명이 필요한 순간이 곧 고쳐야 할 지점이다.

## 5. 자주 나오는 질문과 되물어야 할 것

| 학생이 이렇게 물으면 | 이렇게 되묻는다 |
|---|---|
| 화면이 안 나와요 | 브라우저에 뭐가 떠? 에러 메시지를 그대로 알려 줘 |
| 한글이 깨져요 | contentType 이랑 setCharacterEncoding 둘 다 넣었어? |
| 데이터가 안 보여요 | 서버 쪽에서 SQL 따로 돌려봤어? 결과가 몇 행이야? |
| 시안이랑 달라요 | 스타일 가이드의 어느 항목을 못 지켰는지 짚어 볼래? |
| 어떻게 만들어요? | 지금 어느 화면이야? 그 화면에 뭐가 보여야 하는지 시안에 적혀 있어? |
| 버튼이 안 눌려요 | 콘솔에 빨간 글씨 떠? 그대로 읽어 줘 |
| 정렬을 어떻게 해요? | SQL의 ORDER BY로 해. 자바스크립트로 하면 데이터가 늘수록 느려져 |
| 그래프 라이브러리 뭐 써요? | 안 받아도 돼. canvas에 직접 그리면 축이랑 기준선까지 충분해 |

## 6. 다른 과목과의 접점

**받는 것**
  - 스타일 가이드와 시안 디자인 ← 스마트 문화 앱 콘텐츠 제작
  - 조회할 데이터와 요청 형식 ← 응용 프로그래밍 개발 — 서버
**주는 것**
  - 화면에서 보내는 요청 형식 → 응용 프로그래밍 개발 — 서버

범위 밖 질문이 오면 담당 과목을 알려 주고 그 팀에 요청하라고 안내한다.
