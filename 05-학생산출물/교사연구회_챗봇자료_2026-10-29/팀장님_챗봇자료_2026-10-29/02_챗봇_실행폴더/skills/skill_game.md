## 1. 이 과목이 자율주행차에서 만드는 것

Unity로 만드는 자율주행 테스트 시뮬레이터. 트랙과 차량 물리, 장애물 충돌, 미션·타임어택 로직을 구현하고, 학습 데이터 생성기와 실차 로그 리플레이 기능을 붙인다.

## 2. 최종 도달점 — 완성 판정 기준

- [ ] 엔진 선정 근거서가 있다
- [ ] 실제 트랙과 같은 규격의 가상 트랙이 있다
- [ ] 차량이 속도·가속도 물리로 움직인다
- [ ] 장애물 충돌이 판정되고 부딪히면 멈춘다
- [ ] 미션 성공·실패와 타임어택 기록이 판정된다
- [ ] 주행 화면과 라벨이 쌍으로 자동 저장된다
- [ ] 네트워크 팀이 보낸 실차 주행 로그를 불러와 재생할 수 있다

## 3. 단계별 경로

| 단계 | 해야 할 것 | 완료 판정 | 자주 막히는 지점 |
|---|---|---|---|
| 1. 엔진 선정 | 상용 엔진을 비교해 고르고 왜 골랐는지 근거를 적는다 | 선정 근거서가 있다 | "원래 쓰던 거라서"로 끝냄 |
| 2. 트랙 만들기 | 직선과 원호를 **코드로 이어 붙여** P0 규격대로 만든다 | 한 바퀴 회전각 합이 360도이고 시작점으로 정확히 돌아온다 | 눈대중으로 이어 붙여 시작·끝이 벌어짐(실제로 580 mm 벌어졌다) |
| 3. 차량 물리 | 힘·토크로 차를 굴린다. 물리는 FixedUpdate | 차가 달리고 방향이 0.12초 안에 잡힌다 | 각감쇠를 앞뒤 마찰과 같게 두어 조향 응답이 0.5초로 늘어짐 |
| 4. 자동 주행 | **위치 오차와 각도 오차를 같이 보는 방식**으로 차선을 따라가게 한다 | 중심선 이탈이 주행로 반폭 안에 든다 | 위치만 보고 조향해 커브에서 좌우로 부딪히며 돎 |
| 5. 학습 데이터 생성기 | **카메라 3대**로 [화면 + 조향] 쌍을 저장한다 | 좌우 조향 분포가 한쪽으로 쏠리지 않는다 | 카메라 1대로만 모아 모델이 한 번 벗어나면 못 돌아옴 |
| 6. 실차 로그 리플레이 | 네트워크 팀의 주행 로그 포맷을 읽어 시뮬레이터에서 재생한다 | 실차 주행을 화면으로 되돌려 볼 수 있다 | 로그의 시간 간격을 무시해 재생 속도가 안 맞음 |

**4단계를 조도 센서만으로 하지 마라.** 조도 센서 값의 좌우 차이만 보면
커브에 들어가서야 반응해 부딪히며 돈다. 실차 차선유지처럼
**도로와 몇 도 틀어졌는지**를 함께 봐야 매끄럽게 돈다(Stanley 방식).
자세한 계산은 4절에 있다.

**트랙을 코드로 만들 때 — 닫히는 구조**

직선과 원호를 눈대중으로 이어 붙이면 한 바퀴 돌았을 때 시작점으로 안 돌아온다.
실제로 90도 원호를 이어 붙였다가 **시작과 끝이 580 mm 벌어졌다.**

정확히 닫히는 방법은 두 가지다.

- **타원 고리** — 원호 180도 → 직선 → 원호 180도 → 직선. 제자리로 정확히 돌아온다
- **둥근 사각형** — 마주 보는 모서리끼리 같은 반지름을 쓰면 닫힌다

한 바퀴 회전각 합이 **360도**여야 한다. 0도가 나오면 8자이고, 그 외 값이면 안 닫힌 것이다.

**한 방향으로만 도는 코스를 만들면 안 된다**

타원 하나로 만들었다가 데이터를 모아 보니 **우회전이 한 장도 없었다**(직진 66.8 %).
한 방향으로만 도니 당연한 결과다. 해결은 둘 중 하나다.

- 코스에 반대 방향 회전을 넣는다 — 우 90 → 좌 90 → 좌 90 → 우 90 을 넣으면
  회전이 상쇄되어 방향과 옆 위치가 **정확히 제자리로** 돌아온다(실측 0 mm, 0도)
- 수집을 **양방향**으로 한다 — 같은 코스를 반대로 돌면 좌회전이 그대로 우회전이 된다

둘 다 하면 좌우 불균형이 **1.02배**까지 맞는다.

**차가 도로를 따라가게 하는 법 — 순서대로 확인할 것**

조향이 좌우로 흔들리거나 코스를 벗어나면 아래를 순서대로 본다.
실제로 이 다섯 가지에 전부 걸렸다.

| # | 확인할 것 | 틀렸을 때 증상 |
|---|---|---|
| 1 | **회전 부호** — 유니티에서 +Y 축 회전은 **오른쪽 선회**다 | 왼쪽으로 밀리면 왼쪽으로 더 튼다. 그대로 코스 이탈 |
| 2 | **조향 토크 크기** — 각속도 = 토크 ÷ (관성모멘트 × 각감쇠) | 27배 과하면 조향 12에도 초당 191도로 홱 돈다 |
| 3 | **감쇠비** — 0.7 근처여야 한다 | 0.03이면 −23 → +22 → −73 → +113 mm 로 발산 |
| 4 | **D항 계산법** — 경로 투영값을 미분하지 말고 **실제 횡방향 속도**를 쓴다 | 1 mm 잡음이 조향 60으로 증폭 |
| 5 | **조향 응답 시간** — 각감쇠를 앞뒤 마찰과 같은 값으로 두면 0.5초가 걸린다 | 늦게 먹으니 더 벗어나고, 되잡으면 반대로 넘어간다 |

계산 예시다. 관성모멘트 0.00177 kg·m², 각감쇠 2.0 일 때
조향 60에서 필요한 각속도가 0.625 rad/s 라면 토크는 **0.0094** 여야 한다.
각감쇠를 8.0 으로 올리면(응답 0.12초) 토크는 4배인 **0.076** 이 된다.

**위치만 보면 커브에서 흔들린다 — 각도도 같이 봐라**

차선 위치 오차만 보고 조향하면 커브에 들어가서야 반응해 좌우로 부딪히며 돈다.
실차 차선유지가 쓰는 방식은 **위치 오차와 각도 오차를 같이 보는 것**이다(Stanley).

    조향 = 각도이득 × (도로와 틀어진 각도) − 위치이득 × atan(k × 이탈량 ÷ 속도)

이렇게 하면 각도를 맞춰 커브를 따라 돌고, 위치 항이 남은 거리를 천천히 메운다.
실측 결과 중심선 이탈 **최대 46 mm**(주행로 반폭 150 mm)로 들어왔다.

**속도를 조향에 연동하지 마라**

조향이 크면 속도를 줄이도록 했더니, 속도가 다시 조향에 영향을 줘 서로 흔들었다.
속도는 **일정하게** 두는 편이 안정적이다. 커브 R320 은 0.25 m/s 로 충분히 돈다.

모터 값은 계산으로 바로 나온다. 적분으로 맞추면 0.07 ~ 0.29 m/s 로 요동친다.

    모터 = 목표속도 × 질량 × 마찰 × 255 ÷ 추진력

**도로 조각에 콜라이더를 두지 마라**

도로를 조각 수백 개로 깔면 이음매마다 미세한 턱이 생긴다.
차 바닥이 거기 걸려서 **모터를 135까지 줘도 80 mm 만에 멈췄다.**
도로는 보여 주기만 하고, 부딪히는 몸은 평평한 바닥이 맡게 한다.

**학습 데이터 수집 — 무엇을 저장하나**

[화면 + 그때의 조향값] 쌍을 저장한다. 이것이 자율주행 학습의 재료다.

- 화면은 **128 × 96 흑백** — 크면 라즈베리파이에서 느려진다
- 조향은 **−1 ~ +1 로 정규화** — 실차 모터 값과 무관하게 쓰려는 것이다
- CSV 한 줄에 프레임번호, 조향, 속도, 이탈량을 적는다
- 사람이 수십 바퀴 몰 필요가 없다. **잘 도는 제어기가 운전**하고 그걸 저장한다

**카메라를 3대 두어야 한다 — 이게 핵심이다**

가운데 카메라 하나로만 모으면 **17초 만에 코스를 이탈한다.**
잘 모는 장면만 배우니, 한 번 크게 벗어나면 그 화면을 본 적이 없어 조향을 못 낸다.
조향이 0으로 죽으면서 그대로 나간다. **분포 이탈**이라고 한다.

카메라를 좌우 **60 mm** 로 옮기면 "차가 그만큼 벗어난 화면"이 공짜로 생긴다.
거기에 되돌아오는 조향을 라벨로 붙이면 회복하는 법을 배운다.

    가운데 카메라  →  라벨 = 실제 조향
    왼쪽 카메라    →  라벨 = 실제 조향 + 0.19
    오른쪽 카메라  →  라벨 = 실제 조향 − 0.19

보정값 0.19 는 임의값이 아니다. 차가 60 mm 벗어났을 때 제어기가 실제로 낼 조향이다.

    cross = atan(1.4 × 0.06 ÷ 0.25) = 0.324 rad
    yaw   = −1.1 × 0.324 = −0.357 rad/s
    조향  = −0.357 ÷ 0.0210 = −17  →  정규화 0.19

카메라 1대와 3대의 차이다.

| | 카메라 1대 | 카메라 3대 |
|---|---|---|
| 결과 | 17초 만에 이탈 | **한 바퀴 완주(46초)** |
| 최대 이탈 | 8,269 mm | **122 mm** |
| 도로 안에 있던 시간 | 37 % | **78 %** |

**한글 경로에서 이미지가 저장이 안 된다**

폴더 이름에 한글이 있으면 저장 함수가 **오류 없이 조용히 실패**한다.
"720장 저장 완료"가 찍히는데 폴더는 비어 있다.
저장은 바이트로 인코딩한 뒤 파일에 직접 쓴다.

### 교사 실차 경험의 적용 범위

2026년 10월 교사 시제품의 관찰을 익명화한 진단 사례다. 학생 팀의 성공이나 모든 장비의 표준값을 뜻하지 않는다. 수업 표준과 승인된 팀 규격을 보존하고, 완성본 소스·모델·교사 원본 기록은 공개하지 않는다.

### 교사 실차 사례 — 시뮬레이터와 실제 카메라 조건을 대조한다.

가상 트랙에서 동작한 모델이 인쇄 노면·실제 조명·센서 모드에서 다르게 동작한 교사 사례가 있다. 코드가 실행된 사실과 실물 주행을 구분하고 카메라 높이·각도·실제 화각·선 모양·입력 방향을 비교한다. 교사 한 장비의 카메라 높이를 모든 학생 팀의 확정값으로 바꾸지 않는다.

### 교사 실차 사례 — 경로 완주와 차체 경계 준수를 따로 판정한다.

교사 영상에서는 코스를 완주하면서 일부 코너에서 차체가 안쪽 경계에 걸쳐 보였다. 카메라가 도로를 보고 있거나 중심점이 도로 위에 있다는 사실만으로 바퀴 전체가 안에 있다고 판정하지 않는다. 회전 시점·차체 위치·바퀴 바깥 폭을 확인하고, 영상 원근만으로 치수나 원인을 확정하지 않는다. 완주 기록은 유지하고 경계 준수 항목을 별도로 남긴다.

## 5. 자주 나오는 질문과 되물어야 할 것

| 학생이 이렇게 물으면 | 이렇게 되묻는다 |
|---|---|
| 차가 안 움직여요 | 물리 컴포넌트 붙였어? 힘 주는 코드가 Update야, FixedUpdate야? |
| 속도가 들쭉날쭉해요 | 지금 움직이는 코드가 어느 주기에서 돌고 있어? |
| 닿지도 않았는데 멈춰요 | 충돌 영역을 화면에서 눈으로 봤어? 상자가 차보다 커? |
| 데이터가 학습이 안 된대요 | 몇 장 모았어? 장면이 얼마나 다양해? 같은 각도만 찍은 건 아니야? |
| 라벨을 어떻게 붙여요? | 인공지능 팀이랑 클래스 기준을 정했어? 정지선을 어디까지로 볼 거야? |
| 트랙을 어떻게 만들어요? | P0에서 정한 트랙 폭이랑 차선 폭이 몇이야? |
| 트랙이 안 닫혀요 | 한 바퀴 회전각 합이 몇 도야? 360도가 나와야 해 |
| 차가 코스를 벗어나요 | 조향 부호부터 확인했어? 유니티는 +Y 회전이 오른쪽이야 |
| 좌우로 계속 흔들려요 | 감쇠 항을 넣었어? 경로 위치를 미분해서 쓰고 있진 않아? |
| 조향을 줘도 늦게 돌아요 | 각감쇠를 앞뒤 마찰과 같은 값으로 두진 않았어? |
| 모터를 줘도 차가 안 나가요 | 도로 조각에 콜라이더가 붙어 있진 않아? 이음매에 걸린 거야 |
| 학습이 커브를 못 돌아요 | 조향 분포를 봤어? 우회전이 몇 %야? 한 방향으로만 돌진 않았어? |
| 모델이 한 번 벗어나면 못 돌아와요 | 카메라를 몇 대로 모았어? 회복 데이터가 있어? |
| 실차 로그가 안 읽혀요 | 네트워크 팀 패킷 포맷 문서 받았어? 헤더가 어디서 시작해? |
| 저장했는데 폴더가 비어 있어요 | 폴더 이름에 한글 있어? 저장 함수가 한글 경로에서 조용히 실패하는 경우가 있어 |

## 6. 다른 과목과의 접점

**받는 것**
  - 실차 주행 로그 ← 네트워크 프로그래밍
**주는 것**
  - 시뮬레이터 환경과 합성 학습 데이터 → 인공지능 모델링

범위 밖 질문이 오면 담당 과목을 알려 주고 그 팀에 요청하라고 안내한다.
