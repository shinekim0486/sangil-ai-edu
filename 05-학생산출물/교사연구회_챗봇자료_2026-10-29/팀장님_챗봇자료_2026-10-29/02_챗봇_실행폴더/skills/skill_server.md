## 1. 이 과목이 자율주행차에서 만드는 것

자율주행차 관제 시스템의 서버. 네트워크 팀이 보낸 주행 로그를 데이터베이스에 쌓고, 화면이 요청하면 조회해서 돌려주고, 테스트한 뒤 시스템 운영 팀에 넘겨 배포한다.

> 선생님이 만든 챗봇 서버도 같은 구조다. 요청을 받아 처리하고 로그와 사용량을 DB에 쌓는다. 막히면 그 소스를 열어 보고 참고해도 된다.

## 2. 최종 도달점 — 완성 판정 기준

- [ ] 개발 환경(웹 서버와 DB)이 구축되어 페이지가 뜬다
- [ ] E-R 다이어그램이 있고 그대로 테이블이 만들어져 있다
- [ ] 주행 로그가 데이터베이스에 저장된다
- [ ] 화면이 요청하면 조회 결과를 돌려준다
- [ ] DB 연결 같은 공통 처리가 한 곳에 모여 있다
- [ ] 테스트를 하고 결함을 조치한 기록이 있다
- [ ] 시스템 운영 팀이 받아서 배포할 수 있는 상태다

## 3. 단계별 경로

| 단계 | 해야 할 것 | 완료 판정 | 자주 막히는 지점 |
|---|---|---|---|
| 1. 개발 환경 구축 | 웹 서버와 JDK, Oracle을 설치하고 연결을 확인한다 | 빈 페이지가 뜨고 DB 접속이 된다 | 포트가 이미 쓰이고 있음 / JDBC 드라이버를 못 찾음 |
| 2. 데이터 설계 | 무엇을 저장할지 E-R 다이어그램으로 그리고 DDL로 테이블을 만든다 | 테이블이 생성되고 키가 정해져 있다 | 기본키를 안 정해 중복이 쌓임 |
| 3. 공통 모듈 구현 | DB 연결처럼 반복되는 처리를 한 곳으로 모은다 | 여러 페이지가 같은 코드를 다시 쓰지 않는다 | 페이지마다 접속 코드를 복사해 붙임 |
| 4. 서버 프로그램 구현 | 로그를 저장하고 조건에 맞게 조회하는 기능을 만든다 | 저장한 값이 조회로 되돌아온다 | 값을 문자열로 이어 붙여 SQL을 만듦 |
| 5. 테스트·결함 조치 | 화면과 연결해 인터페이스를 시험하고 결함을 고친다 | 결함 목록과 조치 내역이 있다 | 테스트 없이 바로 넘김 |
| 6. 인계 | 시스템 운영 팀에 실행 방법과 설정을 정리해 넘긴다 | 운영 팀이 다른 PC에서 띄울 수 있다 | 내 컴퓨터에서만 돌아감 |

## 4. 검증된 예시 코드·자료

**우리 수업 방식** — JSP와 Oracle을 쓴다. **2학기 규칙대로 DTO/DAO를 쓴다.** DB 처리(Connection · PreparedStatement · ResultSet)는 DAO 메서드로 빼고, JSP는 DAO를 불러 화면에만 집중한다. 1학기에 만든 로그인·회원가입(JSP 안에서 직접 연결)을 DAO로 옮기고 그 위에 조회 기능을 얹는 것이다. (아래 4절 예시 코드 중 JSP 안에서 직접 연결하는 부분은 교사가 먼저 만들어 본 1학기식 판이다. SQL과 컬럼은 그대로 쓰되 DAO로 옮겨 준다.)

**교사가 미리 만들어 본 결과 — 테이블은 패킷 형식에서 나온다**

새로 설계하지 마라. 네트워크 팀이 정한 센서 패킷 12바이트가 그대로 컬럼이 된다.

```
패킷 PAYLOAD                    drive_log 컬럼
시각(4)   ts_ms        →        ts_ms      NUMBER(10)
앞거리(2) dist_mm      →        dist_mm    NUMBER(5)
조도좌(2) light_l      →        light_l    NUMBER(5)
조도우(2) light_r      →        light_r    NUMBER(5)
속도(2)   speed_mms    →        speed_mms  NUMBER(6)
패킷 헤더 SEQ          →        seq_no     NUMBER(3)   유실률 계산의 근거
```

테이블은 셋이다.

| 테이블 | 담는 것 |
|---|---|
| `run_log` | 주행 회차 — 팀, 시작 시각, 메모 |
| `drive_log` | 주행 기록 — 위 컬럼 + 지연(delay_ms) |
| `event_log` | 이벤트 — 정지선 인식, 긴급 정지 |

**회차로 묶는 이유** — 트랙이 2개뿐이라 팀이 순번제로 돌아가며 달린다.
회차 단위로 묶어야 "1차보다 2차가 나아졌나"를 비교할 수 있다.
이 비교가 「최적화」 능력단위의 개선 전후 근거가 된다.

**테이블 예시**

    drive_log
      log_id     번호 (기본키)
      team_code  팀 코드
      ts         측정 시각
      dist_cm    앞 거리
      light      밝기
      speed      속도
      cmd        명령
      delay_ms   통신 지연

번호는 시퀀스로 자동 증가시킨다.

**반드시 지킬 것**

| 항목 | 값 |
|---|---|
| DB 접근 방식 | **DTO/DAO** — 2학기 규칙. DB 처리는 DAO 메서드로 빼고 JSP는 DAO를 불러 화면만 그린다. JSP 안에서 Connection을 직접 만들지 않는다 |
| SQL에 값 넣기 | **PreparedStatement의 물음표 자리** — 문자열 이어 붙이기 금지. 따옴표 하나로 페이지가 죽는다 |
| JDBC 드라이버 위치 | **WEB-INF/lib** 안. 여기가 아니면 못 찾는다 |

- JDBC 드라이버 파일은 WEB-INF/lib 안에 둔다. 여기가 아니면 못 찾는다
- SQL은 문자열을 이어 붙이지 말고 PreparedStatement 의 물음표 자리에 값을 넣는다.
  재 봤다. `김0훈's 팀`을 넣으면 **near "s": syntax error**로 페이지가 죽고,
  `A-1' OR '1'='1`을 넣으면 **조건을 무시하고 전부 나온다**(3행). 물음표 자리에 넣으면 둘 다 0행으로 막힌다.
  보안 이전에 따옴표 하나로 당장 안 돌아간다
- 다 쓴 자원은 ResultSet, Statement, Connection 순서로 닫는다. 안 닫으면 연결이 쌓여 어느 순간 서버가 멈춘다
- 저장 후 결과가 안 보이면 commit 여부부터 확인한다
- 주행 로그를 보내는 쪽은 PC가 아니라 **라즈베리파이**다. 파이가 카메라를 보고
  조향을 정한 뒤 아두이노에 보내고, 그 기록을 서버로 올린다
- 그래서 저장할 항목이 늘었다. 기존 6개(순번·시각·앞거리·조도 좌우·속도·지연)에
  **모델이 낸 조향값**과 **중심선 이탈량**을 더한다
- 한 회차에 몇 행이나 쌓이나 · 행이 몇 개나 되나 — 한 바퀴 11.14 m 이고 초당 20건이면
  약 **900행**이다. 6팀이 여러 번 돌리므로 조회는 반드시 **회차 단위로 나눠서** 한다

**막혔을 때 순서** — 화면부터 보지 말고 SQL을 SQL 도구에서 따로 돌려 본다. 거기서 결과가 나오면 문제는 자바 쪽, 안 나오면 문제는 SQL 쪽이다. 이 한 가지로 절반이 걸러진다.

## 5. 자주 나오는 질문과 되물어야 할 것

| 학생이 이렇게 물으면 | 이렇게 되묻는다 |
|---|---|
| 연결이 안 돼요 | 에러 메시지를 그대로 보여 줘. 드라이버를 못 찾는 거야, 접속이 거부된 거야? |
| 저장이 안 돼요 | commit 했어? SQL 도구에서 직접 조회했을 때는 보여? |
| 조회하면 아무것도 안 나와요 | 그 SQL을 따로 돌려봤어? 몇 행 나와? |
| 느려요 | 조회하는 행이 몇 개야? 조건 없이 전부 가져오고 있는 건 아니야? |
| 어떻게 만들어요? | 화면에서 뭘 보여줄 건데? 그 화면에 필요한 컬럼부터 적어 보자 |
| 에러가 나요 | 에러 메시지 첫 줄이랑 몇 번째 줄에서 났는지 알려 줘 |

## 6. 다른 과목과의 접점

**받는 것**
  - 화면에서 넘어오는 요청 형식 ← 응용 프로그래밍 개발 — 화면
  - 저장할 주행 로그와 패킷 포맷 ← 네트워크 프로그래밍
**주는 것**
  - 배포할 관제 서버와 실행 방법 → 시스템 운영 및 네트워크 운영

범위 밖 질문이 오면 담당 과목을 알려 주고 그 팀에 요청하라고 안내한다.
